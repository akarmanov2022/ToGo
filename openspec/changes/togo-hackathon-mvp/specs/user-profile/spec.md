# Spec Delta

## Purpose

Описывает пользователя ToGo: его имя, фото, город и категории интересов, чтобы люди понимали, с кем встретятся.
Перечень категорий общий для профилей и событий.

## ADDED Requirements

### Requirement: Перечень категорий

Категории ДОЛЖНЫ (SHALL) быть фиксированным перечнем из семи значений: `PICNIC` «Пикник», `RUN` «Пробежка»,
`EXCURSION` «Поход на экскурсию», `BOARD_GAMES` «Настолки», `QUEST` «Квест», `CINEMA` «Кино» и `CAFE`
«Кафе/Ресторан». Система ДОЛЖНА (SHALL) отдавать по `GET /api/v1/categories` пары `code` и `name` в этом порядке
и ДОЛЖНА (SHALL) требовать действующий токен приложения.

#### Scenario: Клиент загружает перечень

- **WHEN** пользователь запрашивает перечень с действующим токеном
- **THEN** система возвращает семь категорий с кодами и названиями от «Пикник» до «Кафе/Ресторан» в порядке перечня

#### Scenario: Перечень без токена

- **WHEN** клиент запрашивает перечень без токена
- **THEN** сервер отвечает 401 UNAUTHORIZED

### Requirement: Свой профиль

Система ДОЛЖНА (SHALL) возвращать по `GET /api/v1/users/me` профиль текущего пользователя: `id`, `tgId`, `tgLogin`,
`name`, `photoUrl`, `city`, `categories`, `createdEventsCount` и `visitedEventsCount`. Пользователь ДОЛЖЕН (SHALL) иметь возможность сохранить имя, город и набор
категорий через `PUT /api/v1/users/me`. Имя НЕ ДОЛЖНО (MUST NOT) быть пустым, город может отсутствовать, набор категорий
может быть пустым. Категория вне перечня ДОЛЖНА (SHALL) отклоняться с 400 VALIDATION_ERROR.

#### Scenario: Пользователь заполняет профиль

- **GIVEN** вошедший пользователь
- **WHEN** он сохраняет имя «Аня», город «Санкт-Петербург» и категории `CINEMA` и `BOARD_GAMES`
- **THEN** `GET /api/v1/users/me` возвращает это имя, этот город и ровно эти две категории

#### Scenario: Неизвестная категория

- **WHEN** вошедший пользователь сохраняет профиль с категорией `SPORT`
- **THEN** сервер отвечает 400 VALIDATION_ERROR с полем `categories[0]` в `details`

#### Scenario: Пустое имя

- **WHEN** вошедший пользователь сохраняет профиль с именем из одних пробелов
- **THEN** сервер отвечает 400 VALIDATION_ERROR с полем `name` в `details`

### Requirement: Просмотр чужого профиля

Система ДОЛЖНА (SHALL) отдавать вошедшему пользователю по `GET /api/v1/users/{userId}` профиль другого пользователя:
`id`, `tgLogin`, `name`, `photoUrl`, `city`, `categories`, `createdEventsCount` и `visitedEventsCount`. Telegram ID другого пользователя НЕ ДОЛЖЕН (MUST NOT)
возвращаться.

#### Scenario: Пользователь смотрит профиль участника

- **GIVEN** пользователь «Борис» с username «boris_m», городом «Москва» и категорией «Пробежка»
- **WHEN** вошедший пользователь открывает профиль Бориса
- **THEN** сервер возвращает имя «Борис», username «boris_m», фото, город «Москва», категорию «Пробежка» и счётчики
  встреч, но не Telegram ID

#### Scenario: Профиль не существует

- **WHEN** вошедший пользователь открывает профиль с неизвестным идентификатором
- **THEN** сервер отвечает 404 USER_NOT_FOUND

### Requirement: Счётчики встреч

`createdEventsCount` ДОЛЖЕН (SHALL) равняться числу событий, организованных пользователем, в любом состоянии.
`visitedEventsCount` ДОЛЖЕН (SHALL) равняться числу событий в состоянии `finished`, в которых пользователь участвовал,
включая организованные им. Страница профиля ДОЛЖНА (SHALL) показывать имя, username Telegram и оба счётчика.

#### Scenario: Пользователь с историей встреч

- **GIVEN** Анна организовала два события, одно завершилось, другое отменено, и участвовала в завершённом событии Бориса
- **WHEN** Анна открывает свой профиль
- **THEN** профиль показывает «Создано: 2» и «Посещено: 2»

#### Scenario: Выход до срока не считается посещением

- **GIVEN** Борис присоединился к событию, вышел из него до срока регистрации, и событие завершилось
- **WHEN** открывается профиль Бориса
- **THEN** это событие не входит в `visitedEventsCount`

### Requirement: Аватар профиля

Страница профиля ДОЛЖНА (SHALL) показывать `photoUrl`, если он есть. Если фото отсутствует, клиент ДОЛЖЕН (SHALL)
показать запасной аватар с первой буквой имени пользователя.

#### Scenario: Есть фото

- **GIVEN** у пользователя задан `photoUrl`
- **WHEN** открывается его профиль
- **THEN** клиент показывает изображение по этому адресу

#### Scenario: Нет фото

- **GIVEN** у пользователя имя «Анна» и `photoUrl` равен null
- **WHEN** открывается её профиль
- **THEN** клиент показывает запасной аватар с буквой «А»

### Requirement: Архив в своём профиле

Свой профиль ДОЛЖЕН (SHALL) содержать секцию архива: завершённые и отменённые встречи текущего пользователя.
Клиент ДОЛЖЕН (SHALL) запрашивать их через `GET /api/v1/events` с `participating=true`, фильтрами `state` на
`finished`, `cancelled_by_organizer` и `cancelled_by_system`, `order=desc` и `limit=12`. Чужой профиль НЕ ДОЛЖЕН
(MUST NOT) показывать архив.

#### Scenario: Архив своего профиля

- **GIVEN** Анна участвовала в завершённом событии и в событии, отменённом организатором
- **WHEN** Анна открывает свой профиль
- **THEN** клиент запрашивает архив с `participating=true`, нужными `state`, `order=desc` и `limit=12` и показывает
  эти встречи от более новых к более старым

#### Scenario: Чужой профиль без архива

- **WHEN** вошедший пользователь открывает профиль Бориса
- **THEN** клиент не показывает секцию архива и не запрашивает архивные события Бориса
