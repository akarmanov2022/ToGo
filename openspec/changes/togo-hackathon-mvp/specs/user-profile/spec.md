# Spec Delta

## Purpose

Описывает пользователя ToGo: его имя, фото, город и категории интересов, чтобы люди понимали, с кем встретятся.
Справочник категорий общий для профилей и событий.

## ADDED Requirements

### Requirement: Справочник категорий

Система ДОЛЖНА (SHALL) отдавать по `GET /api/v1/categories` полный справочник категорий с идентификатором и названием,
отсортированный по названию и идентификатору. Справочник меняется только миграциями и ДОЛЖЕН (SHALL) требовать
действующий токен приложения.

#### Scenario: Клиент загружает справочник

- **WHEN** пользователь запрашивает справочник с действующим токеном
- **THEN** система возвращает все категории с идентификаторами и названиями, например «Кино», «Настолки», «Спорт»,
  отсортированные по названию

#### Scenario: Справочник без токена

- **WHEN** клиент запрашивает справочник без токена
- **THEN** сервер отвечает 401 UNAUTHORIZED

### Requirement: Свой профиль

Система ДОЛЖНА (SHALL) возвращать по `GET /api/v1/users/me` профиль текущего пользователя: `id`, `tgId`, `tgLogin`,
`name`, `photoUrl`, `city` и `categories`. Пользователь ДОЛЖЕН (SHALL) иметь возможность сохранить имя, город и набор
категорий через `PUT /api/v1/users/me`. Имя НЕ ДОЛЖНО (MUST NOT) быть пустым, город может отсутствовать, набор категорий
может быть пустым. Неизвестная категория ДОЛЖНА (SHALL) отклоняться с 400 CATEGORY_NOT_FOUND.

#### Scenario: Пользователь заполняет профиль

- **GIVEN** вошедший пользователь
- **WHEN** он сохраняет имя «Аня», город «Санкт-Петербург» и категории «Кино» и «Настолки»
- **THEN** `GET /api/v1/users/me` возвращает это имя, этот город и ровно эти две категории

#### Scenario: Неизвестная категория

- **WHEN** вошедший пользователь сохраняет профиль с идентификатором категории, которого нет в справочнике
- **THEN** сервер отвечает 400 CATEGORY_NOT_FOUND с полем `categoryIds[0]` в `details`

#### Scenario: Пустое имя

- **WHEN** вошедший пользователь сохраняет профиль с именем из одних пробелов
- **THEN** сервер отвечает 400 VALIDATION_ERROR с полем `name` в `details`

### Requirement: Просмотр чужого профиля

Система ДОЛЖНА (SHALL) отдавать вошедшему пользователю по `GET /api/v1/users/{userId}` профиль другого пользователя:
`id`, `tgLogin`, `name`, `photoUrl`, `city` и `categories`. Telegram ID другого пользователя НЕ ДОЛЖЕН (MUST NOT)
возвращаться.

#### Scenario: Пользователь смотрит профиль участника

- **GIVEN** пользователь «Борис» с username «boris_m», городом «Москва» и категорией «Спорт»
- **WHEN** вошедший пользователь открывает профиль Бориса
- **THEN** сервер возвращает имя «Борис», username «boris_m», фото, город «Москва» и категорию «Спорт», но не Telegram ID

#### Scenario: Профиль не существует

- **WHEN** вошедший пользователь открывает профиль с неизвестным идентификатором
- **THEN** сервер отвечает 404 USER_NOT_FOUND
