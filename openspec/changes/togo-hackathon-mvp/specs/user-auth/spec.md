# Spec Delta

## Purpose

Позволяет входить в ToGo через Telegram без отдельной регистрации, выходить из системы, а действия, которые меняют
данные, оставляет только вошедшим пользователям. Для демо даёт вход под заранее созданными пользователями.

## ADDED Requirements

### Requirement: Вход через Telegram

Система ДОЛЖНА (SHALL) впускать посетителя по данным виджета Telegram Login с проверенной подписью. Если пользователя с
таким идентификатором Telegram ещё нет, система ДОЛЖНА (SHALL) создать учётную запись с именем, username и фото из
Telegram. При повторном входе система ДОЛЖНА (SHALL) впускать в ту же учётную запись и НЕ ДОЛЖНА (MUST NOT) затирать
имя, которое пользователь изменил в профиле.

#### Scenario: Первый вход

- **GIVEN** в ToGo нет пользователя с идентификатором Telegram 123456789
- **WHEN** посетитель входит через Telegram с идентификатором 123456789, именем «Анна», фамилией «Смирнова» и username
  «anna_s»
- **THEN** система создаёт учётную запись с именем «Анна Смирнова» и username «anna_s», и посетитель входит в систему как
  этот пользователь

#### Scenario: Повторный вход

- **GIVEN** пользователь с идентификатором Telegram 123456789 уже входил и изменил имя в профиле на «Аня»
- **WHEN** он снова входит через Telegram
- **THEN** посетитель входит в ту же учётную запись, новая не создаётся, и имя остаётся «Аня»

### Requirement: Проверка подписи Telegram

Система ДОЛЖНА (SHALL) отклонять вход через Telegram, если подпись данных не совпадает с подписью, вычисленной токеном
бота ToGo, если подписи нет или если время авторизации в Telegram старше одного часа. Отказ НЕ ДОЛЖЕН (MUST NOT)
создавать учётную запись.

#### Scenario: Подделанные данные

- **WHEN** посетитель отправляет данные Telegram, в которых имя изменено после подписи
- **THEN** система отклоняет вход с ошибкой аутентификации о том, что данные Telegram не прошли проверку

#### Scenario: Нет подписи

- **WHEN** посетитель отправляет данные Telegram без подписи
- **THEN** система отклоняет вход с ошибкой аутентификации о том, что данные Telegram не прошли проверку

#### Scenario: Устаревшие данные

- **WHEN** посетитель отправляет правильно подписанные данные Telegram, полученные два часа назад
- **THEN** система отклоняет вход с ошибкой аутентификации о том, что данные Telegram устарели

### Requirement: Демо-вход

Система ДОЛЖНА (SHALL) в профиле `demo` показывать список демо-пользователей и впускать под любым из них без Telegram.
Вне профиля `demo` список и вход НЕ ДОЛЖНЫ (MUST NOT) быть доступны.

#### Scenario: Вход под демо-пользователем

- **GIVEN** приложение запущено в профиле `demo` с демо-пользователем «Борис»
- **WHEN** посетитель выбирает «Бориса» в списке демо-пользователей
- **THEN** посетитель входит в систему как Борис

#### Scenario: Демо-вход выключен

- **GIVEN** приложение запущено без профиля `demo`
- **WHEN** посетитель запрашивает список демо-пользователей или пытается войти под демо-пользователем
- **THEN** система отвечает ошибкой «не найдено»

### Requirement: Выход

Система ДОЛЖНА (SHALL) позволять вошедшему пользователю выйти, после чего запросы из этого браузера считаются
анонимными.

#### Scenario: Пользователь выходит

- **GIVEN** вошедший пользователь
- **WHEN** пользователь выходит
- **THEN** следующий запрос к защищённому действию отклоняется как неаутентифицированный

### Requirement: Текущий пользователь

Система ДОЛЖНА (SHALL) сообщать вошедшему пользователю, под кем он вошёл, чтобы клиент мог восстановить сессию после
перезагрузки страницы.

#### Scenario: Вошедший пользователь спрашивает, кто он

- **GIVEN** вошедший пользователь с именем «Анна Смирнова», username «anna_s» и фото
- **WHEN** клиент запрашивает текущего пользователя
- **THEN** система возвращает идентификатор в ToGo, имя, username Telegram и ссылку на фото этого пользователя

#### Scenario: Анонимный посетитель спрашивает, кто он

- **WHEN** анонимный посетитель запрашивает текущего пользователя
- **THEN** система отвечает ошибкой «не аутентифицирован»

### Requirement: Защищённые действия требуют входа

Система ДОЛЖНА (SHALL) отклонять от анонимного посетителя любое действие, которое создаёт или меняет данные, и любой
просмотр персональных данных. Лента событий, поиск и карточка события ДОЛЖНЫ (SHALL) оставаться доступны без входа.

#### Scenario: Анонимный посетитель пытается создать событие

- **WHEN** анонимный посетитель пытается создать событие
- **THEN** система отклоняет запрос с ошибкой «не аутентифицирован»

#### Scenario: Анонимный посетитель смотрит ленту

- **WHEN** анонимный посетитель открывает ленту событий
- **THEN** система возвращает ленту
