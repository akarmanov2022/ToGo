# Spec Delta

## Purpose

Напоминает участникам о встречах и сообщает о важных изменениях через бота Telegram, чтобы никто не пропустил событие
и не пришёл на отменённое. Это функция второй очереди: делается, только если ядро готово.

## ADDED Requirements

### Requirement: Канал уведомлений

Система ДОЛЖНА (SHALL) отправлять уведомления на русском языке сообщениями бота `@togo_devdays_bot` в личный чат
пользователя по его Telegram ID. Сбой отправки НЕ ДОЛЖЕН (MUST NOT) менять результат действия пользователя или
события. Каждое уведомление ДОЛЖНО (SHALL) доставляться пользователю не больше одного раза для одного события.
Если бот не может писать пользователю, система ДОЛЖНА (SHALL) прекратить попытки для этого уведомления.

#### Scenario: Telegram недоступен

- **GIVEN** Bot API Telegram отвечает ошибкой
- **WHEN** Борис присоединяется к событию
- **THEN** сервер отвечает 200, Борис становится участником, а уведомление отправляется повторно позже

#### Scenario: Пользователь заблокировал бота

- **GIVEN** Борис заблокировал бота
- **WHEN** наступает время уведомления Бориса
- **THEN** система не повторяет отправку этого уведомления

### Requirement: Уведомление о записи

После успешного вступления система ДОЛЖНА (SHALL) отправить вступившему сообщение с названием события и временем
начала. Повторное вступление уже участника НЕ ДОЛЖНО (MUST NOT) отправлять сообщение.

#### Scenario: Пользователь записался

- **WHEN** Борис присоединяется к событию «Вечер настолок»
- **THEN** Борис получает сообщение о записи на «Вечер настолок» с временем начала

#### Scenario: Повторное вступление

- **GIVEN** Борис уже участник события
- **WHEN** Борис снова присоединяется к нему
- **THEN** новое сообщение не отправляется

### Requirement: Подтверждение участия

Когда событие переходит в `registration_closed`, система ДОЛЖНА (SHALL) отправить каждому участнику сообщение
о том, что встреча состоится.

#### Scenario: Минимум набран к сроку

- **GIVEN** событие с минимумом 3 и тремя участниками
- **WHEN** наступает срок регистрации
- **THEN** каждый из трёх участников получает подтверждение участия

### Requirement: Уведомление об отмене

При переходе события в `cancelled_by_organizer` система ДОЛЖНА (SHALL) уведомить всех участников, кроме организатора.
При переходе в `cancelled_by_system` система ДОЛЖНА (SHALL) уведомить всех участников, включая организатора, и указать
причину: не набран минимум. Повторная отмена НЕ ДОЛЖНА (MUST NOT) отправлять сообщения.

#### Scenario: Организатор отменил встречу

- **GIVEN** событие Анны, в котором участвуют Борис и Вера
- **WHEN** Анна отменяет событие
- **THEN** Борис и Вера получают сообщение об отмене, Анна не получает

#### Scenario: Система отменила встречу

- **GIVEN** событие Анны с минимумом 3, в котором участвует Борис
- **WHEN** наступает срок регистрации
- **THEN** Анна и Борис получают сообщение об отмене из-за недобора участников

### Requirement: Напоминания перед встречей

Система ДОЛЖНА (SHALL) напомнить каждому участнику о событии за 24 часа и за 1 час до `startsAt`, если событие в этот
момент не отменено. Напоминание, момент которого прошёл до вступления или создания события, НЕ ДОЛЖНО (MUST NOT)
отправляться. Пользователь, который вышел из события, НЕ ДОЛЖЕН (MUST NOT) получать напоминания о нём.

#### Scenario: Напоминания за день и за час

- **GIVEN** Борис участвует в событии с началом завтра в 19:00
- **WHEN** серверное время достигает сегодня 19:00, а затем завтра 18:00
- **THEN** Борис получает напоминание за день и напоминание за час

#### Scenario: Событие создано меньше чем за сутки

- **WHEN** Анна создаёт событие с началом через пять часов
- **THEN** Анна получает только напоминание за час

#### Scenario: Событие отменено до напоминания

- **GIVEN** событие отменено за два часа до начала
- **WHEN** наступает время напоминания за час
- **THEN** напоминание не отправляется

#### Scenario: Пользователь вышел из события

- **GIVEN** Борис присоединился к событию и вышел из него до срока регистрации
- **WHEN** наступает время напоминаний
- **THEN** Борис их не получает
