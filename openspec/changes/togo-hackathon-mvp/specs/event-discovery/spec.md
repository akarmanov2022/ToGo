# Spec Delta

## Purpose

Помогает найти событие, к которому стоит присоединиться, и вернуться к своим: поиск с фильтрами по названию, категории,
времени, состоянию и участию, постраничная выдача и подробная карточка события.

## ADDED Requirements

### Requirement: Поиск событий

Система ДОЛЖНА (SHALL) отдавать пользователю с действующим токеном события по возрастанию `startsAt`, а при
равенстве — по идентификатору. Без фильтров выдача ДОЛЖНА (SHALL) включать события всех состояний, в том числе
прошедшие и отменённые. Каждое событие ДОЛЖНО (SHALL) возвращаться с актуальным состоянием и признаками
`isParticipant` и `isOrganizer` для текущего пользователя.

#### Scenario: Выдача без фильтров

- **GIVEN** событие, которое начнётся завтра, событие, которое началось вчера, и отменённое событие на послезавтра
- **WHEN** пользователь запрашивает события без фильтров
- **THEN** в выдаче все три события: вчерашнее, завтрашнее, послезавтрашнее

#### Scenario: Поиск без авторизации

- **WHEN** клиент запрашивает события без действующего токена
- **THEN** сервер отвечает 401, клиент выполняет предусмотренный вход Mini App

### Requirement: Пагинация поиска

Система ДОЛЖНА (SHALL) отдавать выдачу поиска страницей по `limit` от 1 до 100 (по умолчанию 20) и `offset` от 0
(по умолчанию 0). Ответ ДОЛЖЕН (SHALL) содержать `total` — число событий после фильтрации до пагинации.

#### Scenario: Пустая выдача

- **WHEN** ни одно событие не подходит под фильтры
- **THEN** сервер отвечает 200 с пустым `items` и `total` 0

#### Scenario: Пагинация

- **GIVEN** пять событий
- **WHEN** пользователь запрашивает `limit` 2 и `offset` 4
- **THEN** в выдаче одно последнее событие, `total` 5

#### Scenario: Недопустимый размер страницы

- **WHEN** пользователь запрашивает `limit` 101
- **THEN** сервер отвечает 400 VALIDATION_ERROR с полем `limit`

### Requirement: Фильтры поиска

Система ДОЛЖНА (SHALL) сужать выдачу по любому сочетанию фильтров, которые выполняются одновременно: `query` —
подстрока названия без учёта регистра, крайние пробелы удаляются, пустая строка не фильтрует; `categoryId` — события
с этой категорией, неизвестная категория даёт пустую выдачу; `state` — состояние после актуализации по серверному
времени; `participating` — участие текущего пользователя.

#### Scenario: Фильтр по названию

- **GIVEN** события «Вечер настолок» и «Футбол во дворе»
- **WHEN** пользователь ищет по `query` « НАСТОЛ »
- **THEN** в выдаче только «Вечер настолок»

#### Scenario: Фильтр по категории

- **GIVEN** события с категориями «Спорт» и «Кино»
- **WHEN** пользователь фильтрует по категории «Кино»
- **THEN** в выдаче только событие с категорией «Кино»

#### Scenario: Фильтр по актуальному состоянию

- **GIVEN** срок регистрации события прошёл, минимум набран, а фоновая обработка ещё не обновила сохранённое `recruiting`
- **WHEN** пользователь фильтрует по `state=recruiting`
- **THEN** событие не попадает в выдачу, а при `state=registration_closed` попадает

#### Scenario: Сочетание фильтров

- **GIVEN** события «Спорт» в состояниях `recruiting` и `cancelled_by_organizer`
- **WHEN** пользователь фильтрует по категории «Спорт» и `state=recruiting`
- **THEN** в выдаче только событие в `recruiting`

### Requirement: Фильтр по времени начала

Система ДОЛЖНА (SHALL) применять `startsFrom` как включительную нижнюю границу начала, а `startsTo` — как
исключительную верхнюю. При обеих границах `startsFrom` ДОЛЖЕН (SHALL) быть меньше `startsTo`.

#### Scenario: Фильтр по времени

- **GIVEN** события с началом в субботу 00:00 и в воскресенье 00:00
- **WHEN** пользователь фильтрует по `startsFrom` субботу 00:00 и `startsTo` воскресенье 00:00
- **THEN** в выдаче только субботнее событие

#### Scenario: Начало диапазона не раньше конца

- **WHEN** пользователь передаёт `startsFrom`, равный `startsTo` или позже него
- **THEN** сервер отвечает 400 VALIDATION_ERROR с ошибкой диапазона времени

### Requirement: Мои события

Система ДОЛЖНА (SHALL) по фильтру `participating=true` возвращать события, в которых текущий пользователь участвует,
включая организованные им, в общем порядке поиска. Клиент ДОЛЖЕН (SHALL) показывать в разделе «Мои события» эту
выдачу с отметкой организатора по `isOrganizer`. `participating=false` НЕ ДОЛЖЕН (MUST NOT) фильтровать выдачу.

#### Scenario: Организованные и чужие события

- **GIVEN** Анна организует событие завтра, присоединилась к событию послезавтра и участвовала в событии вчера
- **WHEN** Анна запрашивает события с `participating=true`
- **THEN** выдача такая: вчерашнее, завтрашнее с `isOrganizer: true`, послезавтрашнее

#### Scenario: Пользователь вышел из события

- **GIVEN** Борис присоединился к событию, а потом вышел из него
- **WHEN** Борис запрашивает события с `participating=true`
- **THEN** этого события нет в выдаче

### Requirement: Карточка события

Система ДОЛЖНА (SHALL) показывать пользователю с действующим токеном полную карточку любого события, включая прошедшие
и отменённые: название, описание, место, иконку, категории, время начала и окончания, `registrationClosesAt`,
организатора, лимиты, `participantsCount`, `availableSlots`, актуальное состояние, `isParticipant` и `isOrganizer`.

#### Scenario: Пользователь открывает карточку

- **GIVEN** предстоящее событие «Настолки в антикафе» с максимумом 6 и 4 участниками, организованное Анной
- **WHEN** Борис, не участник, открывает его карточку
- **THEN** в карточке все поля события, организатор Анна, 4 участника, 2 свободных места, `isParticipant: false`
  и `isOrganizer: false`

#### Scenario: Закрытая регистрация до начала встречи

- **GIVEN** событие ещё не началось, но срок регистрации наступил и минимум набран
- **WHEN** пользователь открывает карточку
- **THEN** отображаются `registration_closed` и срок регистрации; кнопки вступления и выхода недоступны

#### Scenario: Обработка закрытия задержалась

- **GIVEN** срок регистрации прошёл при недоборе, а сохранённое состояние ещё `recruiting`
- **WHEN** пользователь открывает карточку
- **THEN** сервер возвращает `cancelled_by_system`

#### Scenario: Неизвестное событие

- **WHEN** пользователь открывает карточку с неизвестным идентификатором события
- **THEN** сервер отвечает 404 EVENT_NOT_FOUND
