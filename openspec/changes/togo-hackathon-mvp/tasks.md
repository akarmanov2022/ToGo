## 11. Фронтенд: события

Временный режим до подключения Telegram: кнопка «Войти в демо» входит в вымышленный профиль через MSW.
Для публичного демо — отдельная сборка `npm run build:demo` с worker; обычная сборка не обходит авторизацию.
Демо не предоставляет доступ к настоящим данным и не меняет проверку токена на бэкенде.
Для стенда dev-togo.ru Compose передаёт `FRONTEND_MODE=demo` в сборку frontend/Dockerfile;
после доставки кода требуется пересборка фронтенда на сервере. Такая сборка использует настоящий
Telegram-вход при наличии initData и предлагает MSW-демо только в обычном браузере.

Распределение работы: первый фронтендер отвечает за календарь, пикеры начала/окончания/срока регистрации,
валидацию и преобразование этих дат для API, карту и её интеграцию в форму и ленту. Второй фронтендер отвечает
за остальные поля формы, её общую отправку, ленту, карточку события и профиль. Пустые значения дат не получают
скрытых значений по умолчанию; изменение срока регистрации не подменяет начало. Проверка задачи 11.3 общая.

Локально реализована и подключена к форме часть 11.3: модуль `EventSchedule` с тремя независимыми значениями,
пустым начальным состоянием, собственным календарём в стиле приложения и ползунками выбора времени,
преобразованием в RFC3339 с локальным смещением и проверкой порядка сроков. Месячное ограничение применяется
только к началу. Временное решение: начало не раньше завтрашнего дня (завтра с 00:00, не через 24 часа) —
собрано в `earliestEventStart`, чтобы при изменении решения менялось одно место. Форма проверяет обязательные
поля (название из букв/цифр до 100, описание 1–500, одна категория из перечня, минимум ≥ 1, максимум ≥ 2,
минимум ≤ максимум, выбранное место), блокирует кнопку «Создать встречу» при нарушениях и показывает красную
надпись «Пожалуйста, заполните обязательные поля»; «Отмена» выходит без подтверждения; лишние кнопки создания
на странице создания скрыты. Helpers и интеграция формы покрыты тестами, включая календарные границы и переход
DST. Сквозная проверка на настоящем бэкенде ещё не выполнена.

Локально реализована часть 11.1/11.2 по обновлённой аналитике: лента подключена к `GET /api/v1/events`
(`startsFrom=now`, отменённые и завершённые скрываются, порядок по возрастанию начала — умолчание API,
фильтр категории из справочника), кнопка карточки вычисляется по таблице 3.1 (`cardAction` из
`modules/Events/actions.ts`): организатор — «Отменить событие» с подтверждением (`POST /api/v1/events/{id}/cancel`),
участник — «Отписаться от события» (`DELETE .../participants/me`), свободное место — «Присоединиться»
