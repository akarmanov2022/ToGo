# Proposal

## Why

Людям трудно найти компанию для досуга: сходить в кафе, на выставку или на тренировку часто не с кем, а общие чаты и
соцсети не помогают подобрать людей по интересам, месту и времени. ToGo решает это через события, которые пользователи
создают сами и к которым другие могут присоединиться. Проект делается командой из пяти человек за недельный хакатон,
поэтому цель изменения — минимальный продукт, на котором можно показать сквозной сценарий от входа через Telegram до
присоединения к встрече.

## What Changes

- Telegram Mini App автоматически входит по проверенной строке `Telegram.WebApp.initData` при открытии внутри
  Telegram. Формы логина, виджета Telegram Login и отдельной регистрации нет; учётная запись создаётся по Telegram ID.
- Бэкенд выдаёт access token приложения по текущему API; последующие запросы используют Bearer-авторизацию.
  При отсутствии корректных данных Telegram вход не выполняется. Локальные моки не заменяют проверку на сервере.
- Профиль пользователя с именем, фото, городом, набором категорий интересов и счётчиками созданных
  и посещённых встреч.
- Фиксированный перечень (enum) из семи категорий: Пикник, Пробежка, Поход на экскурсию, Настолки, Квест, Кино,
  Кафе/Ресторан. Отдельной таблицы категорий нет.
- Создание события с названием, обязательным описанием до 500 символов, одной категорией, местом, иконкой,
  необязательной точкой на карте, временем начала не позже чем через месяц, временем окончания, лимитами участников
  и заданным организатором сроком регистрации `registrationClosesAt`.
- Изменение события организатором до закрытия набора.
- Лимиты участников события: нижний и верхний, при этом `1 <= min <= max <= 50`.
- Организатор автоматически становится первым участником своего события, не может его покинуть, но может отменить.
- Лента событий со страницами и фильтрами по названию, категории, времени, состоянию, участию и наличию свободных мест.
- Карточка события с текущим числом участников и статусом.
- Присоединение к событию и выход из него разрешены только до `registrationClosesAt`, пока набор открыт.
  Вступление дополнительно требует свободного места; время начала не заменяет срок регистрации.
- Пользователь не участвует в двух событиях, начала которых отстоят меньше чем на три часа: такое вступление
  и создание события отклоняются.
- Состояния соответствуют API: `recruiting`, `registration_closed`, `cancelled_by_organizer`, `cancelled_by_system`,
  `finished`. В `registrationClosesAt` состав фиксируется: при недоборе минимума событие отменяется системой,
  иначе регистрация закрывается. В `endsAt` неотменённое событие завершается.
- Раздел «Мои события»: созданные пользователем и те, где он участвует, через фильтр участия в ленте.
- Архив в своём профиле: завершённые и отменённые встречи текущего пользователя; чужой профиль архива не показывает.
- Отображение событий на карте.
- Комментарии к событию, чтобы участники могли договориться о встрече. Это функция второй очереди: делается, только если
  ядро готово к пятому дню.
- Уведомления сообщениями бота Telegram: о записи, о подтверждении участия, об отмене события и напоминания за день
  и за час до начала. Это тоже функция второй очереди.
- Развёртывание на арендованном облачном сервере с собственным доменом и HTTPS, чтобы демо и вход через Telegram
  работали по публичному адресу.
- CI/CD на GitHub Actions: проверка каждого запроса на слияние и автоматический деплой на сервер из ветки `main`.

Вне этого изменения: раздел «Друзья» и социальный граф, вход по e-mail и паролю, через SMS и других OAuth-провайдеров,
push-уведомления приложения и e-mail, закрытые события с заявками, оценки участников, жалобы и модерация, исключение
участника организатором, мобильные приложения.

## Capabilities

### New Capabilities

- `user-auth`: автоматический вход Mini App по `initData`, Bearer-авторизация и обработка окончания сессии.
- `user-profile`: профиль пользователя с городом, категориями и счётчиками встреч, архив своих завершённых и
  отменённых встреч, перечень категорий, просмотр профиля другого участника.
- `event-management`: создание и изменение события, правила валидации полей и лимитов, лимит пяти активных событий,
  отмена события организатором.
- `event-participation`: присоединение и выход до срока регистрации, соблюдение лимитов, лимит пяти активных событий,
  правила для организатора, переходы состояний события и раздел «Мои события».
- `event-discovery`: лента событий, поиск с фильтрами и порядком `order`, карточка события, отображение событий на карте.
- `event-comments`: комментарии участников под событием (вторая очередь).
- `event-notifications`: сообщения бота участникам о записи, подтверждении, отмене и напоминания (вторая очередь).

### Modified Capabilities

Нет: в проекте пока нет спецификаций.

## Impact

- `api/openapi.yaml`: источник истины для API. Существующие эндпоинты и поля сохраняются; контракт дополняется
  профилем (`PUT /api/v1/users/me`, `GET /api/v1/users/{userId}`), координатами события, фильтром `hasFreePlaces`,
  параметром `order`, ограничениями длины и лимитов, комментариями, счётчиками встреч в профиле и кодами
  `SCHEDULE_CONFLICT` и `ACTIVE_EVENT_LIMIT`. По аналитике контракт однократно сужается: описание события становится
  обязательным и не длиннее 500 символов, а категории становятся перечнем: у события одно поле `category` вместо
  `categoryIds`, фильтр ленты `category` вместо `categoryId`.
- `backend`: реализация сгенерированных интерфейсов API, начиная с `EventsService`, сущности и репозитории JPA, новая
  миграция Flyway поверх `V1__base_structure.sql`, миграция `V3` с категориями-перечнем вместо таблиц категорий, ограничением описания
  и очередью уведомлений, конфигурация Spring Security, планировщик уведомлений.
- `frontend`: Telegram Mini App на базе SPA с автоматическим входом при запуске; в каталоге уже есть каркас Vue.
- `infra/docker-compose.yml`: база PostgreSQL уже описана, для демо понадобится тестовый набор данных. Пароль базы
  переезжает в переменные окружения.
- Новые файлы инфраструктуры: `Dockerfile`, `infra/docker-compose.prod.yml`, `infra/Caddyfile` и workflow GitHub
  Actions в `.github/workflows/`.
- Внешние зависимости: сервис карт для отображения событий на карте; бот Telegram, через которого работает вход
  и отправляются уведомления через Bot API;
  арендованный облачный сервер (VPS) и HTTPS-адрес Mini App, настроенный у бота (до появления сервера — туннель); GitHub
  Container Registry для образов приложения.
