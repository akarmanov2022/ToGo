# Proposal

## Why

Людям трудно найти компанию для досуга: сходить в кафе, на выставку или на тренировку часто не с кем, а общие чаты и
соцсети не помогают подобрать людей по интересам и времени. ToGo решает это через события, которые пользователи создают
сами и к которым другие могут присоединиться. Проект делается командой из пяти человек за недельный хакатон, поэтому цель
изменения — минимальный продукт, на котором можно показать сквозной сценарий от входа через Telegram до присоединения к
встрече.

## What Changes

Поведение API задаёт контракт `api/openapi.yaml` из `main`, модель данных — миграция `V1__base_structure.sql`.

- Telegram Mini App автоматически входит по проверенной строке `Telegram.WebApp.initData` при открытии внутри
  Telegram. Формы логина, виджета Telegram Login и отдельной регистрации нет; учётная запись создаётся по Telegram ID
  и хранит `tgId` и необязательный `tgLogin`.
- Бэкенд выдаёт access token приложения; последующие запросы используют Bearer-авторизацию. При отсутствии корректных
  данных Telegram вход не выполняется. Локальные моки не заменяют проверку на сервере.
- Справочник категорий, который ведёт бэкенд.
- Создание события с названием, описанием, местом `location`, необязательной текстовой иконкой, одной или несколькими
  категориями, временем начала и окончания, лимитами участников и заданным организатором сроком регистрации
  `registrationClosesAt`.
- Лимиты участников события: `1 <= minUsers <= maxUsers`.
- Организатор автоматически становится первым участником своего события, не может его покинуть, но может отменить.
  До срока регистрации организатор может изменить название, описание, иконку, категории, лимиты и сам срок.
- Поиск событий с фильтрами по подстроке названия, категории, диапазону времени начала, состоянию и собственному участию,
  с постраничной выдачей.
- Карточка события с числом участников, свободными местами и состоянием.
- Присоединение к событию и выход из него разрешены только до `registrationClosesAt`, пока набор открыт.
  Вступление дополнительно требует свободного места; время начала не заменяет срок регистрации. Повторное вступление
  и выход не участника не считаются ошибкой.
- Состояния соответствуют API: `recruiting`, `registration_closed`, `cancelled_by_organizer`, `cancelled_by_system`,
  `finished`. В `registrationClosesAt` состав фиксируется: при недоборе минимума событие отменяется системой,
  иначе регистрация закрывается. В `endsAt` неотменённое событие завершается.
- Раздел «Мои события» на клиенте строится фильтром `participating=true`.
- Ошибки возвращаются в формате `ApiError` со стабильным кодом, сообщением и ошибками полей.
- Развёртывание на арендованном облачном сервере с собственным доменом и HTTPS, чтобы демо и вход через Telegram
  работали по публичному адресу.
- CI/CD на GitHub Actions: проверка каждого запроса на слияние и автоматический деплой на сервер из ветки `main`.

Вне этого изменения: профиль с именем, фото, городом и интересами, просмотр чужого профиля, город и координаты события,
карта событий, фильтры по городу и свободным местам, комментарии к событиям, вход по e-mail и паролю, через SMS и других
OAuth-провайдеров, push и e-mail уведомления, закрытые события с заявками, оценки участников, жалобы и модерация,
исключение участника организатором, мобильные приложения.

## Capabilities

### New Capabilities

- `user-auth`: автоматический вход Mini App по `initData`, Bearer-авторизация, текущий пользователь и обработка окончания
  сессии.
- `event-management`: справочник категорий, создание и изменение события, правила валидации полей и лимитов, отмена
  события организатором.
- `event-participation`: присоединение и выход до срока регистрации, соблюдение лимитов, правила для организатора,
  переходы состояний события и список участников.
- `event-discovery`: поиск событий с фильтрами и пагинацией, «Мои события», карточка события.

### Modified Capabilities

Нет: в проекте пока нет спецификаций.

## Impact

- `api/openapi.yaml`: контракт уже описан в `main` и служит источником истины; изменение его реализует.
- `backend`: реализация сгенерированных интерфейсов `AuthApiService`, `UsersApiService`, `CategoriesApiService`,
  `EventsApiService`, сущности и репозитории JPA, новая миграция Flyway с ограничениями и справочником категорий,
  конфигурация Spring Security.
- `frontend`: каркас на Vue 3, Pinia и TanStack Query уже есть; его подключают к API и автоматическому входу Mini App.
- `infra/docker-compose.yml`: база PostgreSQL уже описана, для демо понадобится тестовый набор данных. Пароль базы
  переезжает в переменные окружения.
- Новые файлы инфраструктуры: `Dockerfile`, `infra/docker-compose.prod.yml`, `infra/Caddyfile` и workflow GitHub
  Actions в `.github/workflows/`.
- Внешние зависимости: бот Telegram, через которого работает вход; арендованный облачный сервер (VPS) и HTTPS-адрес
  Mini App, настроенный у бота (до появления сервера — туннель); GitHub Container Registry для образов приложения.
