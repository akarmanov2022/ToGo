# Spec Delta

## Purpose

Позволяет участникам оценить завершённую встречу в Mini App или кнопками бота, а всем пользователям — видеть среднюю
оценку события и рейтинг организатора, собранный из оценок его событий.

## ADDED Requirements

### Requirement: Оценка завершённого события

Система ДОЛЖНА (SHALL) позволять участнику события, кроме организатора, поставить событию в состоянии `finished` оценку
через `PUT /api/v1/events/{eventId}/rating` с телом `{ "score": n }`, где `n` — целое от 1 до 5. Сервер ДОЛЖЕН (SHALL)
ответить 200 с событием, в котором учтена эта оценка.

#### Scenario: Участник оценивает встречу

- **GIVEN** Борис участвовал в событии Анны, и событие в состоянии `finished`
- **WHEN** Борис ставит оценку 4
- **THEN** сервер отвечает 200 с событием, где `myRating` равен 4, а `rating.count` учитывает его оценку

### Requirement: Одна оценка на событие

Пользователь ДОЛЖЕН (SHALL) оценить событие не больше одного раза. Повторная оценка, из Mini App или кнопками бота,
ДОЛЖНА (SHALL) отклоняться с 409 ALREADY_RATED и НЕ ДОЛЖНА (MUST NOT) менять первую оценку. Срока, после которого
первую оценку поставить нельзя, нет: система НЕ ДОЛЖНА (MUST NOT) его ограничивать.

#### Scenario: Повторная оценка

- **GIVEN** Борис поставил завершённому событию оценку 2
- **WHEN** Борис ставит ему оценку 5
- **THEN** сервер отвечает 409 ALREADY_RATED, а `myRating` Бориса остаётся 2

#### Scenario: Оценка спустя месяц

- **GIVEN** событие завершилось 40 дней назад, Борис участвовал в нём и ещё не оценивал
- **WHEN** Борис ставит оценку 3
- **THEN** сервер отвечает 200 и сохраняет оценку

### Requirement: Оценивают только участники

Организатор НЕ ДОЛЖЕН (MUST NOT) оценивать своё событие. Пользователь, который не участвует в событии, включая вышедшего
до срока регистрации, НЕ ДОЛЖЕН (MUST NOT) его оценивать. В обоих случаях сервер ДОЛЖЕН (SHALL) ответить 403 FORBIDDEN
с сообщением на русском и не сохранять оценку.

#### Scenario: Организатор оценивает своё событие

- **GIVEN** событие Анны в состоянии `finished`
- **WHEN** Анна ставит ему оценку 5
- **THEN** сервер отвечает 403 FORBIDDEN, и `rating` события не меняется

#### Scenario: Оценку ставит посторонний

- **GIVEN** Вера не участвовала в завершённом событии
- **WHEN** Вера ставит ему оценку 1
- **THEN** сервер отвечает 403 FORBIDDEN

#### Scenario: Оценку ставит вышедший участник

- **GIVEN** Борис вышел из события до срока регистрации, и событие завершилось
- **WHEN** Борис ставит ему оценку 4
- **THEN** сервер отвечает 403 FORBIDDEN

### Requirement: Оценивается только завершённое событие

Оценка события не в состоянии `finished` ДОЛЖНА (SHALL) отклоняться с 409 INVALID_EVENT_STATE. Перед проверкой сервер
ДОЛЖЕН (SHALL) привести событие к актуальному по серверному времени состоянию и сохранить его, даже если оценка
отклонена. Отменённое событие НЕЛЬЗЯ (MUST NOT) оценить.

#### Scenario: Встреча ещё идёт

- **GIVEN** событие в состоянии `registration_closed`, `endsAt` ещё не наступил, Борис участвует в нём
- **WHEN** Борис ставит оценку 5
- **THEN** сервер отвечает 409 INVALID_EVENT_STATE

#### Scenario: Отменённая встреча

- **GIVEN** событие в состоянии `cancelled_by_organizer`, Борис участвовал в нём
- **WHEN** Борис ставит оценку 1
- **THEN** сервер отвечает 409 INVALID_EVENT_STATE

#### Scenario: Фоновое завершение запоздало

- **GIVEN** сохранённое состояние события `registration_closed`, а `endsAt` уже наступил
- **WHEN** участник ставит оценку 4
- **THEN** сервер отвечает 200, и событие сохраняется в состоянии `finished` с этой оценкой

### Requirement: Проверка запроса оценки

Оценка вне диапазона от 1 до 5, нецелое число, отсутствующее поле `score` и неизвестные поля ДОЛЖНЫ (SHALL) отклоняться
с 400 VALIDATION_ERROR и полем в `details`. Неизвестное событие ДОЛЖНО (SHALL) давать 404 EVENT_NOT_FOUND, запрос без
токена — 401 UNAUTHORIZED.

#### Scenario: Оценка вне шкалы

- **WHEN** участник завершённого события ставит оценку 6
- **THEN** сервер отвечает 400 VALIDATION_ERROR с полем `score` в `details`

#### Scenario: Нулевая оценка

- **WHEN** участник завершённого события ставит оценку 0
- **THEN** сервер отвечает 400 VALIDATION_ERROR с полем `score` в `details`

#### Scenario: Неизвестное событие

- **WHEN** пользователь оценивает событие с неизвестным идентификатором
- **THEN** сервер отвечает 404 EVENT_NOT_FOUND

#### Scenario: Оценка без токена

- **WHEN** клиент отправляет оценку без токена
- **THEN** сервер отвечает 401 UNAUTHORIZED

### Requirement: Оценка в событии

Каждое событие в ответах API ДОЛЖНО (SHALL) содержать `rating` — объект со средним `average`, округлённым до одного знака
после запятой, и числом оценок `count`, или `null`, если оценок нет. Событие ДОЛЖНО (SHALL) содержать `myRating` — оценку
текущего пользователя или `null`, если он её не ставил.

#### Scenario: Средняя оценка события

- **GIVEN** участники поставили завершённому событию оценки 5, 4 и 4
- **WHEN** вошедший пользователь открывает карточку события
- **THEN** `rating.average` равен 4.3, `rating.count` равен 3

#### Scenario: Событие без оценок

- **WHEN** пользователь открывает событие, которое никто не оценил
- **THEN** `rating` равен `null`, `myRating` равен `null`

#### Scenario: Своя оценка видна только себе

- **GIVEN** Борис поставил событию оценку 4, а Вера оценку не ставила
- **WHEN** Вера открывает карточку события
- **THEN** `myRating` равен `null`, а `rating.count` равен 1

### Requirement: Рейтинг организатора

Свой и чужой профиль ДОЛЖНЫ (SHALL) содержать `organizerRating`: сумму всех оценок всех событий, организованных
пользователем, делённую на их число и округлённую до одного знака после запятой, и общее число этих оценок. Без оценок
`organizerRating` ДОЛЖЕН (SHALL) быть `{ average: 0.0, count: 0 }`, а не `null`. Каждая оценка весит одинаково.

#### Scenario: Рейтинг из двух событий

- **GIVEN** первое событие Анны получило оценки 5 и 5, второе — оценку 2
- **WHEN** пользователь открывает профиль Анны
- **THEN** `organizerRating.average` равен 4.0, `organizerRating.count` равен 3

#### Scenario: Организатор без оценок

- **GIVEN** Анна организовала события, но их никто не оценил
- **WHEN** пользователь открывает профиль Анны
- **THEN** `organizerRating.average` равен 0.0, `organizerRating.count` равен 0

#### Scenario: Новая оценка пересчитывает рейтинг

- **GIVEN** у Анны одна оценка 2 от Бориса
- **WHEN** Вера ставит событию Анны оценку 4 и открывается профиль Анны
- **THEN** `organizerRating.average` равен 3.0, `organizerRating.count` равен 2

### Requirement: Просьба бота оценить встречу

Когда событие переходит в `finished`, система ДОЛЖНА (SHALL) один раз отправить каждому участнику, кроме организатора,
сообщение бота с просьбой оценить встречу и пятью кнопками от 1 до 5 звёзд. Отменённые события НЕ ДОЛЖНЫ (MUST NOT)
порождать такие сообщения.

#### Scenario: Встреча завершилась

- **GIVEN** в событии Анны участвуют Борис и Вера
- **WHEN** наступает `endsAt`, и событие переходит в `finished`
- **THEN** Борис и Вера получают по одному сообщению «Встреча «…» завершилась. Оцените её:» с кнопками от 1 до 5 звёзд,
  Анна не получает

#### Scenario: Отмена системой

- **WHEN** событие отменяется системой из-за недобора
- **THEN** никто не получает просьбу оценить встречу

### Requirement: Оценка кнопкой бота

Нажатие кнопки с N звёздами ДОЛЖНО (SHALL) сохранять оценку N от имени пользователя Telegram по правилам
`PUT /api/v1/events/{eventId}/rating`. После сохранения бот ДОЛЖЕН (SHALL) ответить «Спасибо за вашу оценку! Вы помогаете
нам становиться лучше» и убрать кнопки. При отказе бот ДОЛЖЕН (SHALL) показать причину; при повторной оценке он
ДОЛЖЕН (SHALL) также убрать кнопки.

#### Scenario: Участник нажимает четыре звезды

- **GIVEN** Борис получил просьбу оценить завершённую встречу
- **WHEN** Борис нажимает «4 ⭐»
- **THEN** сохраняется оценка 4 от Бориса, бот присылает благодарность, и кнопки исчезают из сообщения

#### Scenario: Повторное нажатие

- **GIVEN** Борис уже оценил встречу в Mini App
- **WHEN** Борис нажимает кнопку в сообщении бота
- **THEN** бот показывает «Вы уже оценили это событие», оценка не меняется, и кнопки исчезают

#### Scenario: Telegram недоступен при ответе

- **GIVEN** Bot API отвечает ошибкой на благодарность
- **WHEN** Борис нажимает кнопку
- **THEN** оценка сохраняется, а webhook отвечает 204, чтобы Telegram не повторял нажатие

### Requirement: Оценка в карточке события

Карточка события ДОЛЖНА (SHALL) показывать среднюю оценку и число оценок, если `rating` задан. Участнику завершённого
события, кроме организатора, ещё не поставившему оценку, карточка ДОЛЖНА (SHALL) показывать выбор от одной до пяти
звёзд; после оценки — его `myRating` без возможности изменить. Остальным выбор НЕ ДОЛЖЕН (MUST NOT) показываться. Ошибку сервера клиент ДОЛЖЕН (SHALL) показать сообщением из `ApiError`.

#### Scenario: Участник оценивает в карточке

- **GIVEN** Борис открывает карточку завершённого события, в котором участвовал
- **WHEN** он выбирает четыре звезды
- **THEN** клиент отправляет оценку 4, показывает обновлённую среднюю оценку и четыре звезды без возможности изменить

#### Scenario: Организатор не видит выбор оценки

- **WHEN** Анна открывает карточку своего завершённого события
- **THEN** клиент показывает среднюю оценку, но не показывает выбор звёзд

#### Scenario: Незавершённое событие

- **WHEN** участник открывает карточку события в состоянии `recruiting`
- **THEN** клиент не показывает выбор звёзд

### Requirement: Рейтинг организатора в профиле

Свой и чужой профиль ДОЛЖНЫ (SHALL) показывать под фото звезду с `organizerRating.average`, в том числе 0.0 без оценок,
и число созданных событий.

#### Scenario: Профиль с рейтингом

- **GIVEN** `organizerRating` Анны — среднее 4.3 из 12 оценок
- **WHEN** открывается профиль Анны
- **THEN** клиент показывает под фото звезду с числом 4.3

#### Scenario: Профиль без оценок

- **GIVEN** `organizerRating` Бориса — среднее 0.0 из 0 оценок
- **WHEN** открывается профиль Бориса
- **THEN** клиент показывает под фото звезду с числом 0.0
