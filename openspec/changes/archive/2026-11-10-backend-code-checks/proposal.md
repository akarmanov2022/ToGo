# Proposal

## Why

Бэкенд уже принимает код от нескольких участников хакатона, но ничто не проверяет запросы на слияние автоматически:
тесты запускаются только вручную, покрытие не измеряется, а стиль и запахи кода Kotlin никто не отслеживает. Чем раньше
появится общий шлюз качества, тем меньше кода придётся чинить задним числом, когда сервисы перестанут быть заглушками.

## What Changes

- `./backend/mvnw -f backend/pom.xml verify` дополнительно измеряет покрытие через Kover и падает, если покрытие
  рукописного кода по строкам или по ветвям ниже 80%. В расчёт не входят только код, сгенерированный из
  `api/openapi.yaml`, и функция `main`.
- Сейчас покрытие ниже порога: 48% строк и 56% ветвей. Изменение доводит его до 80% тестами: заглушки сервисов с ответом
  501 получают тесты, а ветви `ApiErrorHandler` и `ApiFailure` — недостающие сценарии. Неиспользуемый устаревший
  `model/User.kt` удаляется.
- `verify` запускает статический анализатор detekt и проверку форматирования ktlint для основного и тестового кода и
  падает при любом нарушении; базовых файлов с прощёнными нарушениями нет, существующие нарушения исправляются.
- Новый workflow GitHub Actions `.github/workflows/backend.yml` выполняет этот `verify` на каждый запрос на слияние и на
  каждый push в `main` и прикладывает к запуску отчёты покрытия, анализаторов и тестов.
- `AGENTS.md` описывает новые проверки и команду автоисправления форматирования.

Вне рамок изменения: проверки фронтенда, деплой и защита ветки `main` — они остаются задачами 2.5 и 2.6 плана
`togo-hackathon-mvp`.

## Capabilities

### New Capabilities

- `backend-quality-gate`: автоматические проверки бэкенда — тесты, порог покрытия, статический анализ и
  форматирование Kotlin — локально и в GitHub Actions.

### Modified Capabilities

Нет.

## Impact

- `backend/pom.xml`: плагины `kover-maven-plugin`, `detekt-maven-plugin` и `ktlint-maven-plugin`.
- Новые файлы: `backend/detekt.yml`, `.editorconfig` в корне репозитория, `.github/workflows/backend.yml`.
- Новые тесты заглушек сервисов в `itmo.goto.service` и дополнительные сценарии в тестах `itmo.goto.web`.
- Удаляется `backend/src/main/kotlin/itmo/goto/model/User.kt`: на него никто не ссылается, у него нет пакета, а его
  колонки не совпадают с таблицей `users`.
- Существующие исходники Kotlin в `backend/src` правятся под ktlint и detekt без изменения поведения.
- `AGENTS.md`: разделы команд и тестов бэкенда.
- Сборка `verify` становится дольше на время анализа; раннеру GitHub нужен Docker для Testcontainers (есть на
  `ubuntu-latest`).
