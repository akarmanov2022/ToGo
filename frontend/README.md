# ToGo frontend

Vue 3 + TypeScript + Vite, TanStack Query и Pinia. При запуске выполняется автоматический вход Mini App через текущий API-контракт. Лента событий, участие (присоединение, выход) и отмена организатором подключены к API; форма создания отправляет `POST /api/v1/events`. Экран профиля пока на демонстрационных данных. Пока авторизации через Telegram нет, в dev без `initData` срабатывает автоматический моковый вход (см. ниже).

```sh
npm install
npm run dev
npm run build
npm run lint
npm run format:check
npm test
npm run api:generate
```

Для автоматического форматирования файлов: `npm run format`.

Экраны: `/` — события, `/login` — вход, `/create` — создание, `/profile` — профиль. В разработке Vite проксирует `/api` на `http://localhost:8080`.

## Локальная разработка без Telegram и бэкенда

Настоящей авторизации через Telegram пока нет, поэтому в dev без `initData` приложение **предлагает
вход через локальные MSW-моки** (демо-пользователь, баннер тестового режима) — просто запустите `npm run dev`
в обычном браузере. Моки перехватывают API-запросы, включая вход, ленту, участие и отмену; данные вымышленные
и сбрасываются при перезагрузке. Это не серверный демо-вход и не способ получить настоящий токен.

Управление флагом `VITE_MSW_ENABLED` в `frontend/.env.local`:

- без значения — моки включаются сами, только если Telegram `initData` отсутствует (обычный `npm run dev`);
- `true` — моки всегда, даже внутри Telegram (принудительный тестовый режим);
- `false` — всегда настоящий бэкенд: обычный браузер без данных Telegram покажет предложение открыть
  приложение через бота.

Для входа нажмите «Войти в демо» на стартовом экране (автоматического входа в моки больше нет).

Для публикации временного сайта без Telegram выполните `npm run build:demo` и опубликуйте содержимое `dist`.
Эта отдельная демо-сборка включает MSW и `mockServiceWorker.js`; данные вымышленные и живут только в браузере.
Нужен HTTPS (либо localhost) для Service Worker. На уже опубликованный сайт изменения попадут только после
пересборки и деплоя. Обычный `npm run build` по-прежнему не включает моковый вход и worker.

### Временный вход на dev-togo.ru

В `infra/docker-compose.yml` сборка фронтенда временно использует `FRONTEND_MODE=demo`:
после публикации появляется кнопка «Войти в демо» без Telegram. Данные тестовые, изменения
не сохраняются на сервере и не передаются другим пользователям.

После доставки изменений на сервер пересоберите только фронтенд из корня репозитория:

```sh
docker compose -f infra/docker-compose.yml up -d --build --no-deps frontend
```

Если фронтенд развёрнут не через этот Compose, используйте `npm run build:demo` либо передайте
`--build-arg FRONTEND_MODE=demo` при сборке `frontend/Dockerfile`.
Чтобы вернуть настоящий Telegram-вход, установите `FRONTEND_MODE=production` в окружении Compose
и повторите пересборку. Переменная нужна на этапе сборки, а не запуска nginx.

## Настоящий вход внутри Telegram

Нужны работающий API и HTTPS-ссылка на фронтенд (стенд либо туннель к локальному Vite), настроенная у тестового бота.
Бэкенд должен проверять данные токеном именно этого бота. Токен бота и ключ Geoapify во фронтенд не добавляются.
Официальный Telegram SDK передаёт исходный `initData`; клиент отправляет его в `POST /api/v1/auth/telegram`, затем
получает профиль через `GET /api/v1/users/me`. Access token хранится только в памяти. При 401 или окончании часа
сессия очищается и Mini App нужно переоткрыть; refresh и серверный logout контрактом не предусмотрены.

## API для разработчиков экранов

- `src/common/api/schema.ts` — генерируемые типы из `../api/openapi.yaml`, не редактировать вручную.
- `apiRequest<T>` из `@/common/api/client` — JSON-запросы с Bearer, без cookie; поддерживает `signal` для отмены.
- `ApiError.status` и `ApiError.body` — HTTP-ошибка, машинный код и `details` для ошибок полей; `NetworkError` — сеть.
- `useAuthStore` из `@/modules/Auth` — состояние авторизации и снимок личности при входе. Не сохранять токен в storage.
- `useCurrentUser` из `@/modules/Auth` — серверное состояние профиля в TanStack Query; после изменения профиля
  инвалидировать ключ `['current-user']`. Редактируемые данные профиля не дублировать в Pinia.

Автоповторы мутаций выключены; запросы с 4xx не повторяются. Геокодирование ожидает API бэкенда и пока не реализовано.

## Синхронизация с OpenSpec

Задача OpenSpec 1.6 выполнена в `main`: категории стали enum, описание обязательно до 500 символов, у профилей
есть счётчики, добавлен `SCHEDULE_CONFLICT`. Контракт `api/openapi.yaml` и типы `schema.ts` синхронизированы с `main`.

Первый фронтендер отвечает за карту и её интеграцию, календарь и выбор трёх дат, авторизацию и общий API-клиент.
Второй — за остальные поля и отправку формы, ленту, карточки и профиль.

Временные решения, которые команда может изменить:

- Начало события — не раньше завтрашнего дня (завтра с 00:00, а не через 24 часа). Правило собрано
  в `earliestEventStart` из `@/modules/EventSchedule`, чтобы его можно было поменять в одном месте.
- Место встречи выбирается только из готовых точек: `PlacePicker` из `@/modules/Map` показывает маркеры
  переданного списка, под картой — название и адрес выбранного места. Ручной адрес и произвольный клик
  по карте убраны. Контракта готовых мест в API пока нет, форма использует локальный список `demoPlaces`;
  после согласования эндпоинта он заменяется ответом сервера без изменения компонента.

Правила пяти активных встреч и ограничения выбора мест Петербургом не реализованы: до интеграции их нужно
зафиксировать в OpenSpec и API.

В форму создания подключён `EventSchedule`: независимые начало, окончание и закрытие регистрации,
изначально пустые, с проверкой порядка сроков и RFC3339 с локальным смещением, календарём в стиле приложения
и ползунками времени. Форма проверяет обязательные поля (название, описание до 500, категория, место,
минимум ≥ 1, максимум ≥ 2, минимум ≤ максимум), блокирует «Создать встречу» при нарушениях и показывает
красную надпись «Пожалуйста, заполните обязательные поля»; «Отмена» выходит без подтверждения.
Отправка уже подключена к `POST /api/v1/events`, но сквозная проверка на настоящем бэкенде ещё не выполнена.
