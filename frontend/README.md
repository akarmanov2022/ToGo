# ToGo frontend

Vue 3 + TypeScript + Vite, TanStack Query и Pinia. Лента с поиском и подгрузкой, подробная карточка, участие,
отмена организатором с подтверждением, создание события и профили подключены к API. В Telegram вход
автоматический; без Telegram доступна кнопка «Войти в демо» в режиме MSW (см. ниже).

## Быстрый запуск с нуля

Нужны **Node.js 22** и npm (поставляется вместе с Node.js). Команды ниже выполняются из корня
клонированного репозитория; для просмотра интерфейса не нужны Docker, Java, токены или `.env`.

```sh
cd frontend
npm ci
npm run dev
```

Откройте `http://localhost:5173` и нажмите **«Войти в демо»**. Если порт занят, используйте адрес,
который напечатал Vite. Это локальные тестовые данные, не данные опубликованного приложения.
Остановить сервер можно сочетанием `Ctrl+C`. Если ранее создан `frontend/.env.local` с
`VITE_MSW_ENABLED=false`, удалите эту настройку или поменяйте её на `true` для локального демо.
Загрузка подложки карты и реальных мест OSM требует доступа к интернету.

### Проверки и сборки

Следующие команды выполняются в папке `frontend`:

```sh
npm run build
npm run lint
npm run format:check
npm test
npm run api:generate
```

`npm run api:generate` нужен после изменения `api/openapi.yaml`, а не при каждом запуске.
Для автоматического форматирования файлов: `npm run format`.

Для просмотра собранного демо без бэкенда:

```sh
npm run build:demo
npm run preview
```

Откройте `http://localhost:4173` (либо адрес из вывода Vite). Обычная сборка `npm run build`
не предоставляет демо-вход; для реального входа нужен запуск внутри Telegram.
`preview` — локальная проверка сборки, не production-сервер.

Экраны: `/` — события, `/login` — перенаправление на главную, `/create` — создание, `/events/:eventId` — карточка,
`/profile` — свой профиль с архивом, `/users/:userId` — чужой профиль. В разработке Vite проксирует `/api` на `http://localhost:8080`.

## Локальная разработка без Telegram и бэкенда

Telegram-авторизация и бот подключены. Для разработки в dev вне Telegram приложение **предлагает
вход через локальные MSW-моки** (демо-пользователь, явно подписанный тестовый экран) — запустите `npm run dev`
в обычном браузере. Моки перехватывают API-запросы, включая вход, ленту, участие и отмену; данные вымышленные
и сбрасываются при перезагрузке. Это не серверный демо-вход и не способ получить настоящий токен.

Управление флагом `VITE_MSW_ENABLED` в `frontend/.env.local`:

- без значения — моки включаются в dev только вне Telegram без `initData`;
- `true` — моки в локальной разработке вне Telegram; настоящий Mini App никогда не подменяется;
- `false` — всегда настоящий бэкенд: обычный браузер без данных Telegram покажет предложение открыть
  приложение через бота.

Для входа нажмите «Войти в демо» на стартовом экране (автоматического входа в моки больше нет).

Для публикации временного сайта без Telegram выполните `npm run build:demo` и опубликуйте содержимое `dist`.
Эта отдельная демо-сборка включает MSW и `mockServiceWorker.js`; данные вымышленные и живут только в браузере.
Нужен HTTPS (либо localhost) для Service Worker. На уже опубликованный сайт изменения попадут только после
пересборки и деплоя. Обычный `npm run build` по-прежнему не включает моковый вход и worker.

### Демо и настоящий Mini App

`FRONTEND_MODE=demo` оставляет демо только в обычном браузере. В Telegram (по `initData` или
`platform`) даже такая сборка обращается к настоящему API. При отсутствии `initData` в Telegram
она предлагает переоткрыть приложение, а не входить в тестовый профиль. Флаг `VITE_MSW_ENABLED=false`
отключает моки и в demo-сборке. Данные демо не сохраняются на сервере.

При отдельной сборке Docker-образа передайте `--build-arg FRONTEND_MODE=demo` в `frontend/Dockerfile`.
Чтобы полностью исключить демо и вне Telegram, используйте `FRONTEND_MODE=production`.
Переменная нужна на этапе сборки, а не запуска nginx.

## Деплой опубликованного приложения

На `dev-togo.ru` изменения попадают после слияния PR в `main`, не после одного пуша в рабочую ветку.
Workflow `.github/workflows/ci.yml` автоматически выполняет проверки, публикует Docker-образы
и вызывает `.github/workflows/deploy.yml` с SHA коммита. Для обычного обновления ручной запуск не нужен.
В GitHub Actions откройте **ci → запуск для main → Deploy production / deploy**: автоматический
деплой находится внутри этого запуска, а не обязательно в списке ручных запусков «Deploy to VPS».
Если проверки или публикация образов упали, деплой не начнётся; нужно исправить соответствующий шаг.

**Actions → Deploy to VPS → Run workflow** используется для повторного деплоя или отката:
выберите ветку `main` и укажите в `revision` полный 40-символьный SHA коммита, для которого уже
успешно собраны и опубликованы образы. Этот workflow не собирает новые образы.
Не запускайте ручной деплой старого SHA только потому, что отдельный список запусков выглядит старым.
Инфраструктура и секреты описаны в [README репозитория](../README.md).

Если после успешного деплоя виден старый интерфейс, полностью закройте Mini App и откройте заново
из бота; в обычном браузере выполните принудительное обновление страницы (`Ctrl+F5`). Уже открытая
вкладка продолжает выполнять загруженный JS до перезагрузки. Это возможная причина, не подтверждение
проблемы кеша конкретного устройства.

## Настоящий вход внутри Telegram

Нужны работающий API и HTTPS-ссылка на фронтенд (стенд либо туннель к локальному Vite), настроенная у тестового бота.
Для локальной интеграции API запускается отдельно на `http://localhost:8080` по инструкции
в [README репозитория](../README.md). В `frontend/.env.local` задайте `VITE_MSW_ENABLED=false`,
перезапустите Vite и открывайте HTTPS-адрес через Mini App тестового бота, а не как обычную веб-страницу.
Бэкенд должен проверять данные токеном именно этого бота. Токен бота и ключ Geoapify во фронтенд не добавляются.
Официальный Telegram SDK передаёт исходный `initData`; клиент отправляет его в `POST /api/v1/auth/telegram`, затем
получает профиль через `GET /api/v1/users/me`. Access token хранится только в памяти. При 401 или окончании часа
сессия очищается и Mini App нужно переоткрыть; refresh и серверный logout контрактом не предусмотрены.

Отдельной формы «Войти через Telegram» и регистрации нет. Во время автоматического входа — компактный
экран с логотипом и «Открываем ToGo». В обычном браузере — ссылка на `@togo_devdays_bot`, при сетевой
ошибке — повтор, при истёкшей сессии — инструкция переоткрыть Mini App. Разрешение сообщений бота
запрашивается после успешного входа (SDK ≥ 6.9); отказ не мешает работе приложения.

## API для разработчиков экранов

- `src/common/api/schema.ts` — генерируемые типы из `../api/openapi.yaml`, не редактировать вручную.
- `apiRequest<T>` из `@/common/api/client` — JSON-запросы с Bearer, без cookie; поддерживает `signal` для отмены.
- `ApiError.status` и `ApiError.body` — HTTP-ошибка, машинный код и `details` для ошибок полей; `NetworkError` — сеть.
- `useAuthStore` из `@/modules/Auth` — состояние авторизации и снимок личности при входе. Не сохранять токен в storage.
- `useCurrentUser` из `@/modules/Auth` — серверное состояние профиля в TanStack Query; после изменения профиля
  записывать ответ PUT в `currentUserKey(user.id)`. При входе кеш заполняется полученным GET me;
  шапка и профиль разделяют один запрос. Для массовой инвалидации используется префикс `['current-user']`.
  Редактируемые данные профиля не дублировать в Pinia. Поздние ответы завершённой сессии кеш не восстанавливают.

## Архитектура FEOD

Профиль — `feod.profile.md`, единственный источник настроек — `feod.config.json`.
`npm run lint` включает `@o-feod/eslint-structure-plugin`: границы слоёв, публичные `index.ts`,
отсутствие циклов, незнакомых файлов и неразрешённых локальных импортов. Проверки работают и в CI;
`src/app/architecture.test.ts` проверяет, что запрещённые импорты действительно отклоняются.

- `app` — запуск, маршруты, layout и интеграции; `pages` — тонкие адаптеры маршрутов.
- `modules` — доменная логика; другие модули импортируются только через публичный API.
- `common` — отдельные примитивы и универсальные composable (`usePopover`), без barrel-файлов.
- `Events/rules.ts` — единые правила доступных действий и статусов; `actions.ts` только выбирает кнопку.
- `Events/eventForm.ts` — единая валидация полей; создание и редактор добавляют свои проверки сроков/места.
- `Auth` владеет GET текущего пользователя и ключом кеша; `Profile` — сохранением и чужими профилями.
- В публичных API нет неиспользуемых helpers форм и устаревшего отдельного экрана входа.

В профиле нет блока интересов и его редактора (раздел 6 аналитики). `categories` пока обязательно в
`UpdateProfileRequest`, поэтому при сохранении имени клиент передаёт прежнее значение без изменений.
Категории событий не удалены. Город и редактор имени остаются по OpenSpec до отдельного решения команды.

Автоповторы мутаций выключены; запросы с 4xx не повторяются. Геокодирование ожидает API бэкенда и пока не реализовано.

## Синхронизация с OpenSpec

Задача OpenSpec 1.6 выполнена в `main`: категории стали enum, описание обязательно до 500 символов, у профилей
есть счётчики, добавлен `SCHEDULE_CONFLICT`. Контракт `api/openapi.yaml` и типы `schema.ts` синхронизированы с `main`.

Первый фронтендер отвечает за карту и её интеграцию, календарь и выбор трёх дат, авторизацию и общий API-клиент.
Второй — за остальные поля и отправку формы, ленту, карточки и профиль.

Временные решения, которые команда может изменить:

- Начало события — не раньше завтрашнего дня (завтра с 00:00, а не через 24 часа). Правило собрано
  в `earliestEventStart` из `@/modules/EventSchedule`, чтобы его можно было поменять в одном месте.
- Место встречи выбирается только из готовых точек: `PlacePicker` из `@/modules/Map` показывает маркеры
  переданного списка, под картой — название и адрес выбранного места. Ручной адрес и произвольный клик
  по карте убраны. `Map/vectorPlaces.ts` извлекает POI из настоящих MVT-тайлов OpenFreeMap/OSM библиотеками
  `@mapbox/vector-tile` и `pbf`. TileJSON — `https://tiles.openfreemap.org/planet`, дата выгрузки не хардкодится.
  Первоначально показан центр Петербурга; после перемещения карты — «Найти места в этой области».
  Максимум 36 тайлов z14, два параллельных запроса, кеш до 64 тайлов, не более 300 мест в результате.
  Токен ToGo и cookie не передаются; атрибуция источников сохранена. Если адреса нет, показаны название и город.
  TanStack Query кеширует категорию и область 30 минут, смена поиска отменяет старый запрос.
  При отказе тайлов резерв — Overpass по bbox; для настолок без board_games в векторном слое также ищутся
  исходные теги OSM. Обычные кафе за клубы настолок не выдаются; эта категория ещё требует живой проверки.
  В Chrome проверена успешная реальная выдача: 88 PICNIC, 11 CINEMA, 300 CAFE, 25 QUEST, 88 RUN, 260 EXCURSION.

Карта ленты больше не сбрасывает зум по таймеру: одинаковые точки не вызывают `fitBounds`, колёсико включено.
Совпадающие координаты — маркер со счётчиком и popup выбора из всех событий; события без координат поясняются.
В подробной карточке есть отдельная карта места, без ссылки обратно на ту же карточку.

Лимит пяти активных участий проверяется в форме создания на клиенте; серверный код `ACTIVE_EVENT_LIMIT`
и параметр `order` ещё ожидаются в контракте. Пока архив собирает все страницы и сортирует полный список
на клиенте (не разворачивает только первую страницу). После расширения контракта перенести сортировку
и пагинацию архива на сервер. Каталог мест работает без API мест бэкенда и без демо-подмены.

В форму создания подключён `EventSchedule`: независимые начало, окончание и закрытие регистрации,
изначально пустые, с проверкой порядка сроков и RFC3339 с локальным смещением, календарём в стиле приложения
и кастомными переключателями часов/минут (минуты с шагом 5). Форма проверяет обязательные поля (название,
описание до 500, категория, место, `1 <= минимум <= максимум <= 50`), не отправляет запрос при нарушениях и показывает
красную надпись «Пожалуйста, заполните обязательные поля» только после попытки сохранения;
кнопки пикеров и выбор категории не включают ошибки. То же правило действует в редакторе события.
«Отмена» выходит без подтверждения.
Поле эмодзи убрано: категория автоматически определяет иконку в запросе, карточках и превью
(🧺 пикник, 🏃 пробежка, 🏛️ экскурсия, 🎲 настолки, 🔎 квест, 🎬 кино, ☕ кафе).
Отправка уже подключена к `POST /api/v1/events`, но сквозная проверка на настоящем бэкенде ещё не выполнена.

## Обновление аналитики 12.11.2026

В своём и чужом профиле под фото показан рейтинг организатора из API (`organizerRating`, без оценок — 0.0).
Чужой профиль показывает созданные пользователем события всех состояний со ссылками в карточку,
но не его личные участия. Пока сервер не предоставляет фильтр по организатору, фронт просматривает
публичный каталог постранично и отбирает `organizer.id`; при большом каталоге нужен серверный фильтр.
В карточке завершённого события участник (кроме организатора) может один раз поставить 1–5 звёзд;
успешный ответ обновляет кеш, повторная оценка недоступна. Оценка из Telegram-бота работает на сервере.
Отзывы из пункта 8.1 аналитики не входят в эту реализацию; существующий чат события сохранён.
В ленте загрузка участия изолирована по событию и не меняет соседние кнопки.
